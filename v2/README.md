# Markdown Reference — Native V2

Offline Rust port of the **own** Recommended extension at [`6933819bb52944ac5db4c517f932ffa24a95497e`](https://github.com/almatkai/markdown-reference/tree/6933819bb52944ac5db4c517f932ffa24a95497e). The single command remains `markdown-reference`, titled **Search Markdown Syntax**, with description **Quickly search up how to format with Markdown**. The original V1 tree is retained; its root README links here.

The embedded data preserves all 15 topics in their source order, every description, basic and additional example, and optional HTML field. V1 never renders those HTML fields. Search lowercases the query and matches prefixes of the first two title words, without trimming or ranking. `View` displays the exact Markdown produced by the own `Reference.tsx` and escape library; `Back` restores the search draft and filtered list. Source declares no preferences, forms, storage, clipboard actions or browser actions. URLs inside examples remain pinned source content, not event-supplied effect targets.

`src/lib.rs` is a standalone Cargo library requiring Rust 1.85 and only `serde_json` at runtime. Data is embedded at compile time; JavaScript, Bun, network access and external data downloads are absent from the product runtime. `adapter/v2_markdown_reference.rs` is the concrete asynchronous beta adapter and uses the real SDK's view/unchanged responses. There are no added public RPCs or notification APIs.

Action IDs are fresh per rendered screen and search, and only IDs in committed host state are accepted. A process-wide nonce also advances for discarded staged searches, preventing a cancelled view's IDs from becoming valid later. Refresh and load-more return `unchanged` without mutating state or minting IDs. Effects cannot be derived from arbitrary payload text, indices or URLs. Invalid calls leave legitimate actions retryable. Disposal, relaunch and navigation invalidate earlier IDs. The source has no clipboard write path, so no clipboard success is asserted or synthesized.

The manifest is schema 2, canonical ID `com.tezbar.native.markdown-reference`, replacing `raycast.markdown-reference`. Command and platform metadata match the own source. Original author `codedbyjordan`, contributor `ridemountainpig`, and own port author `almatkai` are credited in the description because the pinned schema rejects a root `author` field. Original manifest metadata, including categories, is retained in the source fixtures. Both macOS and Windows verification remain `not-run`.

`provenance.json` pins and hashes the own source, Raycast original `6734d85992290066fd31a7f5bee3cca3d3545a1a`, and beta API `fd300e276356587726566026f072563eb9c34cb1`. `assets/markdown-reference.png` retains all 8,159 original bytes, SHA-256 `fe30cefd83f704a1b406a56c7b145676a62fee1f3733f1af68d9863dcd6f4a90`. Original and own MIT notices are byte-exact; beta fixtures and their notice are Apache-2.0. Reference content attribution and CC BY-SA 4.0 terms are retained separately. See [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

[INTEGRATION.md](INTEGRATION.md) describes stable vendoring, compiled dispatch registration, the renderer icon destination and rebuilding. A manifest or marker cannot dynamically load this Rust code. [VALIDATION.md](VALIDATION.md) records executable checks and their limits.

Beta renders supported `List`, `List.Item` and `Detail` nodes. Its spacing, Markdown rendering and action overlay differ from Raycast. List selection resets to the first visible row after returning from Detail because this beta exposes no controlled selection property. For a nonempty query with no results, beta hardcodes application-oriented empty text. Its action shortcut is Meta+K and some labels remain macOS-oriented on Windows; this port adds no unsupported shortcut or renderer props. Button/action routing is tested; real desktop keyboard, UI, clipboard and browser behavior on either OS has not been tested.
